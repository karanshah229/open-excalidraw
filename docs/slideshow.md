# Slides on a continuous board

Choose **Components → Slide** in the drawing toolbar and drag around content. Slides, ordinary Frames, and sketches coexist. A collapsed **Slides · count** button appears under Library only when at least one slide exists, using the native Library button styling. Expanding it reveals a single panel header with Slideshow on the left and collapse on the right. Opening the native sidebar closes Slides; opening Slides closes the native sidebar. Slide buttons move clear of the native sidebar while it is open. The collapsed button shows the slide count; the expanded panel shows the count in navigation below the header. The Slides panel supports automatic numbering, reordering, duplication, previous/next navigation, and speaker notes. Click **Slideshow** to launch a clean fullscreen presentation without audience controls. Its dropdown offers **Slideshow** and, for editors, **Presenter view**, which opens a windowed single-slide audience view and a separate controls/notes window. Arrow keys navigate and Escape exits. Removing a slide boundary preserves its drawings. Fullscreen uses a separate cropped audience surface; exiting restores the board without changing its camera.

## Architecture

- Slides are native Excalidraw `frame` elements tagged with `customData.agenticWhiteboard.slide = { schemaVersion: 1, orderKey }`. Native frame membership, movement, clipping, serialization, and undo remain authoritative. Slides have no editable title; canvas labels, list entries, and preview labels use only **Slide 1**, **Slide 2**, and so on. Old native frame names are ignored, and the editor blocks native title editing for Slides while preserving it for ordinary Frames. Numbering is derived from rational order keys, with ID tie-breaking for concurrent insertions; rank collisions are rebalanced during a move. Ordinary frames need no migration.
- `features/scene/scene-session.ts` observes scene changes before the editor's permission/save gates. It copies the element array because the engine can reuse arrays during mutation. Viewer updates therefore refresh the panel without enabling editing or moving the camera.
- `features/slides/slide-commands.ts` shares versioned, undoable reorder/duplicate/remove operations across the UI and MCP. Duplication remaps child IDs and bindings. The package patch adds atomic Slide creation and derived frame-label hooks in both engine builds; see `patches/README.md` for upgrade requirements.
- Thumbnail and audience rendering share the native frame crop exporter and follow the board’s theme/background. Visible thumbnails render first. One second after the Slides panel opens, offscreen thumbnails warm into the same cache. A serial queue prioritizes visible/presentation renders over background warm-up; closing the panel or presenting cancels pending warm-up work. Per-slide invalidation bounds export work. A board-local, 32 MiB cache shares generated image bytes across slide views, keyed by content fingerprint and resolution. Reopening reuses cached bytes; refreshes keep the previous image until a successful replacement is ready, including when a refresh fails. Display URLs are released on replacement/unmount, and the cache clears when the board or identity changes. Presentation retains the editor instance and isolates keyboard input. Slideshow opens a clean audience view in the main window and requests browser fullscreen; leaving fullscreen ends the presentation rather than returning to a windowed slide. Audience navigation remains available through the keyboard; presenter controls and End are in the separate window. Editors can select **Presenter view** from the Slideshow dropdown to open a separate popup with private notes, a large current-slide preview on the left, notes on the right, a bottom slide thumbnail strip, navigation, note text-size controls, and a pause/reset timer. Presenter view does not request fullscreen or enter it when the audience window is clicked. Escape from the audience or presenter window ends the presentation and closes the presenter popup. Browser fullscreen denial falls back to the clean windowed view. Notes are read-only in Speaker view; editing and conflict resolution stay on the board. Viewers never get this action. Share only the main presentation window or put it on an extended projector display. Desktop mirroring can expose the speaker popup.
- Speaker notes use a separate IndexedDB cache and the `slideNotes` callable. The server rechecks current editor access and board/project lifecycle inside a transaction. Revision conflicts preserve the local draft and expose both versions. Notes never enter scene JSON, element replication, MCP results, or audience slide images. Local drafts are partitioned by user and board; reconnect/reopening retries pending writes. Duplicate operations copy notes separately.

## Deployment and limits

Deploy the newly exported `slideNotes` Firebase function alongside the frontend for cloud notes. It uses the existing `SYNC_ACCESS_FUNCTION_REGION` and `ASSET_ENFORCE_APP_CHECK` configuration. Direct Firestore access to its top-level collection remains denied by the existing rules. Local-only boards work without Firebase.

Native frame constraints apply: each element has one `frameId`, overlapping slides cannot share ownership, and ordinary Frames cannot be nested inside Slides. Surrounding board content can still be included by crop geometry. Fullscreen uses raster previews; a 2560-pixel target bounds export resolution. PDF/PPTX export, remote control, autoplay, are later work.

Notes are retained when a slide boundary is deleted so undo can recover them; deleted boards/projects immediately lose callable access. Permanent note cleanup/retention policy is deferred. Pending cloud drafts retry while their notes editor is open or on reopening, rather than through a background outbox.

## Verification

- `pnpm test:slides`: model/ordering/replication checks and an isolated local browser contract.
- `pnpm test:slides:prod`: production build plus actual production toolbar/creation, preview, notes, fullscreen, and reload checks.
- `pnpm test:slides:notes`: isolated Firebase emulator authorization, revision/idempotency, revocation, and deletion checks. Requires Java for Firestore.
- `node tests/run-regression-tests.mjs --test=slides-shared.test.mjs`: shared viewer updates, reorder/camera stability, cloud notes, reload, and audience privacy.
- `tests/board-loading.test.ts` covers owner-local recovery from transient cloud reads and rejects unauthorized fallback. The shared browser suite verifies owner-local recovery and protection of another owner's cached board; the local browser suite verifies error-to-Retry recovery.
- Existing board behavior, collaboration, and image production suites guard frame reload, saving/access, collaboration, and earlier package patches.

The approved design is in [the implementation plan](plans/slideshow-implementation-plan.md). Source APIs are intentionally narrow; further editor extraction is not a prerequisite for this feature.

Speaker view uses a React portal into a same-origin popup, sharing the main presentation controller’s active slide and scene directly. There is no second editor, cloud navigation channel, or duplicated presentation state. The Microsoft-style arrangement uses Excalidraw design tokens for surfaces, text, inputs, borders, radii, selection, focus, and icon weight; the popup follows the board’s light/dark theme. Native styles/theme are copied to the popup. Closing it leaves the audience running; reopening restores the current slide and notes. Ending the presentation, losing editor access, or unmounting the board closes the popup. Reloading the main board ends the session. A blocked popup shows an actionable message in the audience controls.
