# Freemium implementation and rollout

Implemented in the workspace on 2026-10-03. The eight freemium callable endpoints have now been deployed to **development only** (`open-excalidraw-dev-2`, `us-central1`) for live browser validation. The app runs locally on port **15176** against that real project. Hosted frontend, restrictive rules, and new background jobs remain undeployed; existing dev project-sharing rules/triggers from another worktree were preserved. Production is unchanged. The complimentary email configuration already exists in both Firebase projects. No payments, subscription webhooks, economics agent, or automatic monetary spending cap is enabled.

## Server accounting

Authenticated callable functions own private/shared board commits, image reservations, live session admissions and permanent deletion. Firestore transactions allocate board/storage/save allowances and deduplicate operation IDs. Shared activity uses the board owner's entitlement and usage; guests do not consume their own board allowances. Direct client scene/counter/config writes are denied by rules. Live element mutations also pass through a server function, with session and UTF-8/document size checks. RTDB remains the transport for elements, cursors and presence.

Usage is inventoried once under a server lease, including retained inactive boards, actual private/shared document copies and existing image objects. Existing over-limit accounts retain their documents; new resource allocations are rejected. Image bytes are reserved before upload, with path/size/MIME/uploader grants validated by Storage rules. Finalize/delete events and expired reservation cleanup reconcile usage. Permanent board deletion revokes upload grants, deletes cloud objects/history/live state, and releases its slot; ordinary deletion now performs this permanent cloud purge.

| Firebase location                                                     | Purpose                                                                                  | Client access                                |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------- |
| `adminConfig/complimentaryUsers`                                      | Verified-email permanent Pro list, separately managed in dev/prod                        | None                                         |
| `accountEntitlements/{uid}`                                           | Manual Pro invitation: `{plan: "pro", active: true, expiresAt?: UTC epoch milliseconds}` | None; effective plan comes from callable API |
| `accountUsage/{uid}`                                                  | Current retained boards, image/document bytes, UTC-day logical saves                     | Own summary read; no writes                  |
| `accountUsage/{uid}/boards/{boardId}`                                 | Document copy sizes, logical scene hash, project and deletion state                      | None                                         |
| `accountUsage/{uid}/operations/{hash}`                                | Retry deduplication; cleaned after seven days                                            | None                                         |
| `assetGrants/{sha256(storagePath)}`                                   | Reserved/complete/deleting immutable image uploads                                       | None                                         |
| `projectUsage/free`, `projectUsage/pro`, `projectUsage/complimentary` | Shared UTC-day successful logical saves                                                  | None                                         |
| `adminConfig/freemiumPolicy`                                          | Operator controls: `freeCloudPaused` and positive integer `freeDailySaves`               | None                                         |
| `proAccessRequests/{uid}`                                             | Verified user's request for manually granted Pro; grants no entitlement                  | None                                         |
| RTDB `sessionGrants/{boardId}/{sessionId}`                            | Expiring, server-allocated live session slots                                            | Own grant read/removal; no creation          |

Complimentary resolution uses the current Firebase Auth account's verified email, trimmed and lowercased. It never trusts a requested plan, supplied email, or subscription redirect. Removing the email or changing it revokes complimentary access on the next protected server operation. Manual grants can be revoked or given an expiry. Both retain Pro resource ceilings. Billing integration can later introduce a separate verified entitlement source.

## Limits and alerts

| Feature                                               | Free                        | Pro / complimentary                       | Free warning / critical                                              |
| ----------------------------------------------------- | --------------------------- | ----------------------------------------- | -------------------------------------------------------------------- |
| Retained cloud boards                                 | 3                           | Unlimited count within storage allowances | 2 / 3 boards                                                         |
| Retained image storage                                | 25 MiB                      | 1 GiB                                     | 20 / 23.75 MiB                                                       |
| Individual image                                      | Less than 5 MiB             | Less than 10 MiB                          | 4 MiB warning; rejected at 5 MiB                                     |
| Current board documents, across private/shared copies | 5.27 MiB                    | 100 MiB                                   | 80% / 95%                                                            |
| One board document, every plan                        | 900 KiB                     | 900 KiB                                   | 700 / 850 KiB in board/sync dropdown; server rejection above 900 KiB |
| Registered live sessions per board                    | 3                           | 10                                        | Capacity notice at 3; next admission rejected                        |
| Successful logical scene saves per UTC day            | 1,000                       | 5,000                                     | 800 / 950                                                            |
| Recovery snapshots per board                          | Last 10, at most 7 days old | Last 50, at most 30 days old              | Retention disclosed; oldest history pruned                           |
| Total recovery history per owner                      | 26.37 MiB                   | 250 MiB                                   | Retention ceiling; current scenes are preserved                      |
| Serialized live element, every plan                   | Less than 256 KiB UTF-8     | Same                                      | 200 / 240 KiB; rejected at 256 KiB                                   |

The shared Free pool defaults to **2,000 logical saves/day across all Free owners**, configurable with `freeDailySaves`. `freeCloudPaused: true` rejects new Free cloud mutations/uploads/session admissions while retaining existing cloud data and allowing reads/permanent deletion. Complimentary and manually granted Pro are exempt from this Free pool gate. These controls do not cap all billed reads, writes, storage, function overhead, or network traffic. The proposed $10 production/$5 development subsidy targets still require operator monitoring; no billing automation or notifications are installed.

The account dialog shows actual server usage, reset time, Free/Pro comparison ($6/month or $60/year as proposed future pricing), and complimentary status. Pro requests record interest without charging or granting access. Warning dismissals persist locally and synchronize through browser storage events; critical capacity stays visible. Universal size failures do not suggest that upgrading removes the safety ceiling.

Private local edits remain in IndexedDB when cloud sync fails. Subsequent edits preserve the retry delay; daily quota retries resume at the next UTC day. Guest/shared edits have a separate IndexedDB recovery cache, cleared only after the matching cloud acknowledgement and restored with element reconciliation on reload. Pending guest work is retried after its quota delay, with the latest scene retained while waiting. Local editing/export and local MCP remain unrestricted. A live-session capacity failure opens a read-only snapshot; temporary network failures do not disable local editing.

## Validation

Run `pnpm test:freemium`. Requires Firebase CLI, Java, installed dependencies, and Chrome (or `CHROME_PATH`). It builds Functions, starts isolated **demo-only** Auth/Firestore/RTDB/Storage/Functions emulators, runs server and browser checks, and shuts them down. Ports are declared in `firebase.freemium-test.json`; the suite uses an isolated temporary directory to avoid colliding with another Storage emulator's blob files. It never connects to development or production.

Validation result: 17 server integration checks and the browser suite pass; workspace TypeScript checks and the frontend production build pass. Changed-code lint has no errors (one pre-existing unused collaboration parameter warning).

Server checks cover concurrent allocations, duplicate saves, owner attribution, UTC reset/no-ops, direct SDK/rules bypass attempts, image reservation/upload/delete, forged sessions, UTF-8/document limits, manual/complimentary revocation, inventory, retention and the pooled circuit breaker. Browser checks cover threshold banners, Pro requests, complimentary CTAs, desktop/mobile rendering, recovery reload, and keeping the fourth board locally with its quota retry delay.

## Deployment order

1. Validate Firebase frontend configuration separately for dev/prod; the production build in this workspace is a compilation check, **not a deployable environment-configured bundle**. Set `VITE_FIREBASE_SYNC_ACCESS_FUNCTION_REGION` to match deployed callables. Both `.firebasestorage.app` application buckets exist in Mumbai, outside the new-bucket US-only storage free allowance.
2. Set Functions regions from each environment's actual resources. Production uses Singapore RTDB and Mumbai Firestore. A live dev recheck on 2026-10-03 found Firestore in `nam5`, an RTDB endpoint/deployed triggers in `us-central1`, and Storage in `ASIA-SOUTH1`. Dev callables therefore stay in `us-central1`; Storage triggers belong near the Mumbai bucket. Keep existing regional settings when deploying.
3. Deploy Functions first, before restrictive rules. Verify Admin SDK Auth/Firestore/RTDB/Storage access and cross-service Storage rule access. Trigger service-account permissions are required in real projects; emulators do not establish IAM readiness.
4. Deploy the compatible frontend and rules in a coordinated dev release. Existing cached clients using direct writes will fail once rules close those paths; require them to reload. Do not deploy the current frontend build without the environment configuration above.
5. Smoke-test dev with the verified complimentary owner, a synthetic Free owner, guest editing, image uploads/deletion, offline reload and live session capacity. Review server inventory before the production release. Deploy the same compatible frontend/functions/rules to production with its own configuration.
6. Monitor aggregate Firebase usage manually. Use the operator pause if the subsidy is exceeded. Native listeners are not exact per-user byte meters; registered session limits do not guarantee a socket-count or traffic cap. Raw operation costs can exceed the Free allowance even before the shared logical-save cap.

## Live browser review

Start the app with its ignored dev Firebase configuration using `pnpm --filter @agentic-whiteboard/whiteboard dev --host 127.0.0.1 --port 15176 --strictPort`. Run `FREEMIUM_LIVE_PROJECT=open-excalidraw-dev-2 node tests/freemium-live-ui.test.mjs`, then `node tests/freemium-feature-slideshow.mjs`. Screenshots, test results and the self-contained slideshow are saved under ignored `logs/freemium-live/`; the run log is `logs/freemium-live-e2e.log`.

The live suite requires an authenticated Firebase CLI owner account and the eight deployed callable endpoints. It creates a disposable verified user, signs a Firebase custom token using an in-memory temporary service-account key, and revokes the key immediately after token exchange. It does not enable email/password auth or change IAM roles. The temporary complimentary email is added/removed with an update-time precondition that preserves concurrent family-list edits. Fixture Auth, Firestore and RTDB records are removed in `finally`; real shared usage totals are not rewritten. Google sign-in popup, production rollout, new background jobs and real-cloud direct-write rule denials are not covered by this live suite. The image-usage warning is shown using an explicitly seeded counter on the disposable account.

Live result on 2026-10-03: **11 checks passed**, nine actual app screenshots captured, and slideshow image loading/navigation/mobile layout passed. A separate read-back verified removal of the temporary Auth user, Firestore records, live session grants and complimentary email, while retaining the requested permanent complimentary member. The emulator suite was rerun after fixing stale Free-limit messages on transition to Pro; all 17 integration checks and browser checks passed again. The live suite covers actual cloud board creation, early/critical alerts, fourth-board rejection with canvas drawing retained through reload, image and daily-save caps, session admission, Pro requests, seeded image warnings and complimentary access.

## Deliberately deferred

Payment gateway/subscription lifecycle, controlled asset-download serving and byte quotas, automatic billing-cost attribution/alerts, the economics-monitoring agent, and an interactive history-restore UI. Unreferenced images remain retained for undo/recovery until their board is permanently purged; selective image garbage collection requires a reference/retention policy. Private outbox commits are throttled to five seconds and cursors to ten updates/second; shared durable saves retain the existing idle debounce, so further shared-save coalescing needs collaboration testing before changing it.
